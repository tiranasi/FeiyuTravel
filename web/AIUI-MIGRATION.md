# 从本机开发版迁移到 AIUI

## 2026-11-12 当前范围优先

最新产品为 [POCKET.md](POCKET.md)：只迁移当次对话、主动看一眼、四个成就，**不迁移** 下文旧版的长期记忆、经济或旅行。共享核心改用 `lib/pocket.js`，平台存档只映射 `{version:1,unlocked:[成就ID]}`。本机使用独立 IndexedDB，不碰旧存档；AIUI 使用自有 wx key。当前设备的关闭/重启持久性和模型上下文已通过独立诊断，见 [实测报告](../docs/RUNTIME-20261112.md)。

每次显示会话只保留最近六轮文本；这属于产品预算，不是模型窗口上限。主动观察成功后，只保留该次画面的简短文字描述，不在后续每轮重发照片。退出、隐藏、取消时销毁活动模型请求；隐藏结束当次上下文，重显从新话题开始。宿主可能保留旧页面实例，因此不能只依赖 onUnload 才清理。

模型只发允许列表中的成就事件，应用校验事件、当前请求与前置条件后去重落盘。实测 toolcall 可能伴随空回答；此时显示对应的一句本地反馈，不把空字符串当网络失败，不编造未支持的 tool-role 续接。

眼镜单屏：角色＋一行状态，滑动选择「聊一句 / 看一眼 / 成就」；大字展示短句，较长内容以后接语音。电脑侧栏不搬到镜片上。只缓存 A 首版绿线 8 帧（180×240 RGBA，共约1.32MiB），继续完整画面只 flush 一次。视口480×320为本项目当前设置，单绿光学观感仍需佩戴验收。相机曝光、语音输入、播报和整条集成尚不在本轮验收范围内。

以下保留历史完整原型的迁移分析，不作为当前待实现清单。

## 当前本机玩法版的新增边界

共享核心现为 `lib/game-state.js`、`game-engine.js`、`game-render.js`、`pet-content.js`，原 `pet-*` 是兼容导出。`storage.read/write` 已允许返回 Promise；迁移时可以用 Promise 包装 wx 的同步或异步存储。存档升级至version 2，当前本机长期记忆在IndexedDB，并保留v1迁移、备份与多窗口修订号保护；不能假设其配额与事务语义可直接套到AIUI。

本机增加彩色场景和按显示尺寸提高分辨率的后台画布，逻辑坐标仍是480×320。这些属于本机体验，未在眼镜验收。浏览器原始角色缓存384×512，而眼镜0.2.0保持180×240；未来迁移按设备预算降采样并验证。单绿模式为开发预览，不是镜片光学模拟。游戏中的虚拟远游和预写手记不表示调用了定位或语言模型。

## 约束基线

当前已验证设备是 RG_glasses，项目视口 480×320。A 首版绿线更适合常驻，缓存 Canvas 已获用户实机“不闪”确认。动作像素缓存初始预算 10–20MiB 是开发预算，不是设备上限。开发预算不受限，不改变眼镜自身的内存、电量与显示约束。

本机先迭代角色行为、状态转换、内容、记忆与界面；集成阶段集中验收硬件。不会把浏览器流畅、模拟识别成功当作 AIUI 运行成功。

## 平台接口

共享引擎通过以下接口访问平台：

```js
createPetEngine({
  clock: { now: () => timestampMilliseconds },
  storage: { read: () => savedObjectOrNull, write: object => saveObject(object) },
  vision: { observe: async () => ({ label: '物体名称', source: 'simulation' }) },
  onChange: (state, status) => updateHostControls(state, status)
});
```

浏览器的 `vision` 目前只返回模拟数据。接入真实模型时应扩展明确的设备来源类型、时间和请求标识，并保留模拟数据标签；当前 `local / simulation` 的来源格式不应被默认为已支持真实模型记忆。识别框坐标、置信度、物体跟踪和持续视觉同样尚未实现。

## AIUI 映射

1. **页面**：创建单一 `.ink` Page，在 `app.json` 声明路由，默认导出页面逻辑，保留 480×320 画布。电脑开发工具面板不进入产品界面。
2. **离屏缓存**：用 `new Canvas(180, 240)`、`createImageData`、`putImageData` 准备帧，复用已验收过的缓存加载路线。`drawImage` 的来源必须是 Canvas，不能传 HTML 图片对象。
3. **画面提交**：共享 `renderPet` 先绘制到完整离屏画布；用 `wx.createCanvasContext(id)` 将它复制至显示画布，然后只提交一次 `flush()`。上下文不可用时可取消重试，不静默转用图片组件。
4. **交互**：页面 `onKeyDown / onKeyUp` 调用引擎配对输入；`bindtap` 调用同一确认动作。镜腿滑动不是浏览器触摸事件；实际映射仍按当前设备复核。
5. **生命周期**：`onShow` 恢复引擎与调度；`onHide` 暂停并取消观察；`onUnload` 清除计时器、失效请求、释放缓存和模型会话。
6. **存档**：用已支持的 `wx.getStorageSync / setStorageSync` 替换 localStorage 接口，保持相同可序列化数据格式。测试重开、升级、失败提示、导入和清理范围；不能假设浏览器存储配额就是 AIUI 配额。
7. **视觉与模型**：接当前眼镜 CAMERA 流程及自带 `LanguageModel`。图像输入使用已支持的 image_url 结构，工具调用事件由应用校验并执行，绝不直接执行模型文本。沿用已验证的相机曝光等待与取消逻辑，在模型适配层处理超时和结果校验。

## 内容迭代顺序

1. 先在本机确定家园、互动、旅行、回忆的主要流程和信息密度。
2. 完善角色状态、动作资源、事件库、旅行奖励与记忆摘要规则；将模拟场景做成可重复的用例。
3. 将真实模型响应整理为匿名的离线回放样本，加入同一套校验与状态测试；模型接入与采样需要届时的真机集成。
4. 功能内容稳定后接 AIUI 适配层，集中验收摄像、模型、语音、真实按键、存档、功耗与长时间运行。

建议保留已有眼镜缓存播放版作为渲染基线。若新增了未经真机验证的能力，应在集成阶段单独验收；无需每修改一段文案或一个菜单就重新安装。
