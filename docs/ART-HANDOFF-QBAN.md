## 1. 使用方式

1. 每开一个新对话，先上传角色原稿 `output/references/dafeiyu-20261112/character-standard.png`。它在本仓库的上一级目录，是用户提供的 Q 版三视图。
2. 粘贴第 3 节的「总设定」，等它回复确认。
3. **画风现已确认**：每次同时上传原稿与第 0 节的用户确认图；已验收的批次 A 还可用于精确对齐动作帧。后续批次沿用确认图的比例、线宽与明暗层级。
4. 每次只发一个批次的提示词，一张图对应一个批次（最多 8 格）。格子太多时，模型容易画错数量、画乱比例。
5. 不满意的单格可以要求单独重画，并说明「保持与 A 批次相同的头身比、线宽和配色」。
6. 成图按第 5 节命名，放进 `output/references/dafeiyu-20261112/qban-v2/`。

优先级：**P0** 现有代码马上能用；**P1** 体感（IMU）互动和瞬移；**P2** 旅行、明信片和道具。建议按 A → B → E1 → C → E2 → D → F → G → H 的顺序画。

## 2. 黑底绿色画风的锁定方式

以第 0 节的确认图为视觉基准，直接绘制黑底绿色素材：

- **外轮廓**：鲜亮绿色、粗且连续，小尺寸下剪影清楚。
- **内部线**：较细且明显更暗，接近墨绿/黑绿，保持参考图的层级；具体亮度以参考图为准。
- **填充**：暗绿色块面，头发、裙子、围裙与耳鳍通过暗部层次区分，保留参考图的柔软体积感。
- **配色**：黑底和绿色系，目标显示绿色为 #40FF5E。生成结果的精确色值在接入前核对，技术适配保持已确认的明暗关系。
- **细节**：发缕、荷叶边、衣褶简洁清楚；保留鲸鱼围裙图案、星形眼睛高光等身份特征。
- **效果**：不额外画光晕、模糊、投影、扫描线、文字或漫画符号。全息扫描、闪烁、溶解由游戏叠加。

最终尺寸很小：全身图约 126px 高，胸像约 196px 高。绘制后要检查缩小辨识度。画风已确认与技术验收分别记录；参考图保持原样。

## 3. 总设定（每个新对话的第一条消息，整段复制）

```
你是这个项目的角色动画原画师。我上传了两张参考图：彩色原稿锁定原创角色「大肥鱼」的身份，黑底绿色确认图锁定后续素材的画风。请按绿色确认图的亮外轮廓、暗内部线和暗绿块面来画。接下来我会分批请你画她的动作和表情素材，用于一款 AR 眼镜上的桌宠游戏。请严格遵守以下设定，每张图都要遵守，不需要我重复。

【角色锁定——必须与设定图一致】
- 约 2.2 头身的 Q 版女孩，头大身小，脸圆，大眼睛（保留星形高光，转换为绿色层次），表情软萌。
- 头发：与原稿形状一致的超长波浪卷发，用暗绿块面表现，几乎垂到小腿；头顶一根弯曲的呆毛；刘海遮住部分额头，侧边有几缕垂发。
- 头饰：白色荷叶边女仆头箍；头部两侧各有一只像鲸鱼鳍一样的耳鳍（上深下浅、边缘带羽状褶）；画面右侧（她的左侧）耳鳍上方有一个小蝴蝶结。
- 服装：长袖连衣裙女仆装、荷叶边围裙，围裙中央有小鲸鱼图案；领口有蝴蝶结和圆形胸针；裙摆与袖口有荷叶边。全部用确认图的绿色层次表现，省略细碎刺绣。
- 荷叶边短袜，圆头玛丽珍鞋，用绿色明暗区分。
- 身后有一条鲸鱼尾巴，从裙后伸出，尾鳍在一侧向上翘，尾巴腹面浅色。
- 不要改变发型、服装和尾巴；配色遵守绿色确认图，不要加帽子、背包等设定外的物件，除非提示词明确要求。

【画风——严格沿用用户确认的黑底绿色版本】
- 背景纯黑 #000000，无其他背景元素。
- 绿色系单色，目标显示绿色 #40FF5E；色彩与明暗观感以用户确认图为准。
- 外轮廓鲜亮绿色、粗且连续闭合（512px 格子约 5–6px）。
- 内部线条比外轮廓细且明显更暗，接近墨绿/黑绿；保持确认图的暗线观感，清楚交代五官、发缕与衣服结构。
- 暗绿色填充块面，保留确认图中头发、裙子、围裙、耳鳍的层次与柔软体积感。
- 发缕 5–6 大束，荷叶边用整齐波浪边，围裙鲸鱼简洁清楚。眼睛保留星形绿色高光。
- 保持确认图的圆润脸型、头身比、线宽与细节密度；每批变化集中在指定姿势和表情。
- 禁止额外发光/光晕/辉光、模糊、投影、地面阴影、扫描线、噪点、纹理、边框、文字、水印或签名。
- 漫画符号由程序添加，除非批次明确要求。
【版式与技术规格】
- 画布 2048×1024，均分为 4 列 × 2 行，每格 512×512。不要画格子线，只是按这个网格摆放。
- 每格只画一个姿势，姿势之间至少留 24px 黑色空隙，任何部分（包括头发、尾巴）不能越出自己的格子或和相邻格重叠。
- 全身图：角色总高约 400px（含呆毛），脚底统一落在格子内 y=480 的水平线上（跳跃姿势除外），水平居中。所有全身格的头部大小必须一致。
- 胸像：头顶在格子内 y≈40，胸部下沿被格子底边截断，水平居中，所有胸像格的头部大小一致。
- 侧面姿势一律朝画面右侧（游戏会镜像得到朝左）。
- 格子数量少于 8 时，剩余格子保持纯黑。
- 每格从左到右、从上到下编号 1–8，按我给的编号顺序摆放。

确认理解后只回复「已锁定设定」，然后等我发第一个批次。
```

## 6. 给接收素材的开发代理

- **美术约束不变**：游戏内互动画面里的角色只能来自用户确认的 Q 版素材。载入页的成年全息线稿保持原样，不由本批次替换。
- **转换与接入**：后续输入为黑底绿色素材，保留图中已确认的亮外轮廓、暗内部线与暗绿填充关系。
  - 当前 `tools-art/convert.py` v2 的白底泛洪、彩色分类和自动勾线用于旧彩色素材；接收新绿色批次前需新增独立单色读取路径，勿将黑底图直接交给白底彩色流程。
  - 黑底无需去白底；单通道亮度取 `max(R,G,B)`，按实际图像尺寸的 4×2 网格切格。接入前核对精确绿色色值、画布尺寸、空格和基线。
  - 全身格使用同一比例，以已验收 `body_front` 的高度确定 126px 标准；胸像目标约 196px 高，沿用底边淡出。坐姿、蹲下、跳跃等只记录基线/位置偏移，保持人物尺度一致。
  - 生成图的原生分辨率可能与 2048×1024 不同，实际尺寸与技术适配结果要分别记录；原始画风参考始终原样保留。
  - 单色路径、预览和体积确认后，再通过转换工具更新 `lib/sprite-data.js`；本次仅记录画风与参考，转换脚本和游戏资源尚未更改。
- **镜像**：侧面类素材生成 `L` 镜像。有明确左右区别的素材（`bust_tilt_left/right`、`peek_edge`）不要用镜像代替。
- **体积**：每个全身精灵约 126×90 单通道，约 11KB，base64 后约 15KB；胸像约 40KB。全部 80 格约 1.5–2MB 的 base64，会拉长首屏解码时间。建议：
  - P0 素材随包加载。
  - P1/P2 按需分组解码，或者只在进入对应画面时才解码。
  - 解码依然走现有的分块预算。
  - 上真机检查首帧耗时和内存。
- **渲染**：不要用 `ctx.rotate / scale / transform` 来做歪头、翻转。所有角度变化都用预生成素材，Canvas 方法白名单见 `docs/LVFEIYU.md`。
- **体感互动**：`nod` 和 `shake` 事件在 0.4.0 真机日志中出现过。歪头、转头、抬头需要基于 `AbsoluteOrientationSensor` 的姿态角，阈值、保持时间和冷却时间都要先用只记录日志的版本让佩戴者试用后再定。
- **光学观感**：截图只能证明像素。填色亮度是否合适，由佩戴者在镜片上判断；如果偏亮或偏暗，在素材转换时统一调整亮度并保持已确认的明暗层级，记录佩戴者反馈。
