# 旅行肥鱼 Q 版动画素材：清单与绘制交接（2026-11-12，正常色版）

本文档给负责出图的模型（ChatGPT 图像生成）使用，也给之后接收素材的开发代理使用。

- **第 1～2 节**：给你自己看，说明怎么用。
- **第 3 节**：整段复制给 ChatGPT，作为每次对话的第一条消息。
- **第 4 节**：按批次逐条发送。
- **第 6 节**：写给接收素材的开发代理。

---

## 1. 使用方式

1. 每开一个新对话，先上传角色原稿 `output/references/dafeiyu-20261112/character-standard.png`。它在本仓库的上一级目录，是用户提供的 Q 版三视图。
2. 粘贴第 3 节的「总设定」，等它回复确认。
3. **先只画批次 A（基础三视图）**。你确认满意后，把批次 A 的成图也作为参考图上传，再画其他批次。之后每张图都同时参考原稿和批次 A，这样角色比例、线条粗细和配色才能保持一致。
4. 每次只发一个批次的提示词，一张图对应一个批次（最多 8 格）。格子太多时，模型容易画错数量、画乱比例。
5. 不满意的单格可以要求单独重画，并说明「保持与 A 批次相同的头身比、线宽和配色」。
6. 成图按第 5 节命名，放进 `output/references/dafeiyu-20261112/qban-v2/`。

优先级：**P0** 现有代码马上能用；**P1** 体感（IMU）互动和瞬移；**P2** 旅行、明信片和道具。建议按 A → B → E1 → C → E2 → D → F → G → H 的顺序画。

## 2. 为什么画正常色，再由程序转换

眼镜显示屏只有一种绿色（#40FF5E），黑色等于透明，越亮越挡住现实。镜片上的最终效果是「线稿加淡填色」：

- **外轮廓最亮**：小尺寸下也能认出她。
- **内部是暗绿平涂**：有体积感，又能透出背后的现实。脸比头发亮一档，表情才认得出。
- **全息效果由游戏程序叠加**：扫描线、闪烁、溶解都不用画。

但这个效果**不让 ChatGPT 直接画**。素材一律画成和设定图一样的**正常色**，再用 `tools-art/convert.py` 统一转换：

- **角色更稳**：模型照着彩色设定图画 Q 版最拿手；直接画绿线黑底时，容易加发光、画错风格。
- **效果统一、可调**：轮廓亮度、勾线、各部位填色亮度都在转换脚本里统一设定。80 格出来是同一种风格；戴上后觉得太亮或太暗，改参数重新转换即可，不用重画。
- **彩色原图可复用**：应用图标、宣传图、手机预览都能用。

转换的原理决定了对原画的要求：
- 外轮廓按「白底以外的剪影」自动描，所以**背景必须纯白**。
- 白色衣物必须有**闭合的深色勾线**，否则会和白底连在一起被抠掉。
- 内部线条来自原画里的**深色勾线**。
- 填色按颜色分类：肤色、白布、金饰、蓝色系各对应一档亮度。所以**颜色要和设定图一致、平涂**。

最终尺寸很小：全身图约 126px 高，胸像约 196px 高。所以细节必须**粗、少、清楚**。

## 3. 总设定（每个新对话的第一条消息，整段复制）

```
你是这个项目的角色动画原画师。我上传的图是原创角色「大肥鱼」的 Q 版设定图（上排正面、侧面、背面，下排四个表情胸像）。接下来我会分批请你画她的动作和表情素材，用于一款 AR 眼镜上的桌宠游戏。请严格遵守以下设定，每张图都要遵守，不需要我重复。

【角色锁定——必须与设定图一致】
- 约 2.2 头身的 Q 版女孩，头大身小，脸圆，大眼睛（蓝色瞳孔，里面有星形高光），表情软萌。
- 头发：深蓝色、发梢渐变成浅蓝的超长波浪卷发，几乎垂到小腿；头顶一根弯曲的呆毛；刘海遮住部分额头，侧边有几缕垂发。
- 头饰：白色荷叶边女仆头箍；头部两侧各有一只像鲸鱼鳍一样的耳鳍（深蓝，下缘浅蓝带羽状褶）；画面右侧（她的左侧）耳鳍上方有一个浅蓝色小蝴蝶结。
- 服装：深藏青色长袖连衣裙女仆装，裙摆有金色刺绣花纹和金色小蝴蝶结；白色荷叶边围裙，围裙中央有一个蓝色小鲸鱼图案；领口有深色蝴蝶结和蓝色圆形胸针；裙摆下一圈白色荷叶边；袖口白色荷叶边。
- 白色荷叶边短袜，深藏青色圆头玛丽珍鞋。
- 身后有一条蓝色鲸鱼尾巴，从裙后伸出，尾鳍在一侧向上翘，尾巴腹面浅色。
- 不要改变发型、服装、配色和尾巴，不要加帽子、背包等设定外的物件，除非提示词明确要求。

【画风——与设定图相同的正常色 Q 版赛璐璐】
- 背景：纯白 #FFFFFF，整张图没有任何其他背景元素，没有地面、阴影、渐变背景。
- 配色严格沿用设定图：深蓝/浅蓝头发、深藏青裙子、白色围裙和荷叶边、浅肤色、蓝色眼睛、金色饰品。不要改色、不要整体偏色、不要加滤镜。
- 勾线：深藏青色或近黑色的清晰勾线，外轮廓最粗（在 512px 格子里约 4–5px），内部线约 2–3px，线条闭合。白色部分（围裙、荷叶边、头箍、袜子）外面一定要有完整的勾线，不能和白色背景直接相连。
- 上色：平涂赛璐璐，每种颜色最多一层阴影色，不要柔和渐变、喷枪、写实光影。
- 细节要粗、少、清楚：发缕分成 5–6 大束即可，不画细碎发丝；荷叶边简化成整齐的波浪边；围裙鲸鱼图案画成简单的剪影。
- 眼睛：瞳孔高光和星形高光用纯白，要清楚可辨。腮红用 2–3 道短斜线或小块平涂，不要大面积模糊。
- 禁止：发光/外发光/辉光、模糊、柔边、投影、地面阴影、噪点、纹理、背景、边框、文字、水印、签名。
- 禁止画漫画符号（♪、z、汗滴、爱心、闪光等）——这些由游戏程序添加。除非提示词明确要求。

【版式与技术规格】
- 画布 2048×1024，均分为 4 列 × 2 行，每格 512×512。不要画格子线，只是按这个网格摆放。
- 每格只画一个姿势，姿势之间至少留 24px 白色空隙，任何部分（包括头发、尾巴）不能越出自己的格子或和相邻格重叠。
- 全身图：角色总高约 400px（含呆毛），脚底统一落在格子内 y=480 的水平线上（跳跃姿势除外），水平居中。所有全身格的头部大小必须一致。
- 胸像：头顶在格子内 y≈40，胸部下沿被格子底边截断，水平居中，所有胸像格的头部大小一致。
- 侧面姿势一律朝画面右侧（游戏会镜像得到朝左）。
- 格子数量少于 8 时，剩余格子保持纯白。
- 每格从左到右、从上到下编号 1–8，按我给的编号顺序摆放。

确认理解后只回复「已锁定设定」，然后等我发第一个批次。
```

## 5. 交付与命名

- 每个批次一张 PNG，命名为 `lvfy-qban-<批次>.png`，例如 `lvfy-qban-A.png`、`lvfy-qban-C1.png`。
- 某一格重画时，单独存成 `lvfy-qban-<批次>-<格号>.png`，例如 `lvfy-qban-E1-7.png`，开发代理会用它替换原格。
- 全部放在 `output/references/dafeiyu-20261112/qban-v2/`，不要覆盖原稿 `character-standard.png`。

### 验收清单（每张图都要过一遍）

- [ ] 背景纯白，没有阴影、地面、渐变（放大看角色脚下和边缘）
- [ ] 配色与设定图一致，没有整体偏色或滤镜
- [ ] 角色特征齐全：呆毛、耳鳍、蝴蝶结（她的左侧）、围裙鲸鱼图案、鲸鱼尾巴
- [ ] 同批次所有格的头部大小一致，全身格脚底在同一高度
- [ ] 勾线深色、清晰、闭合，外轮廓比内部线粗；白色衣物外面都有勾线
- [ ] 上色是平涂（最多一层阴影），没有柔和渐变
- [ ] 转换检查：发给开发代理用 `convert.py --sheet` 转一遍，看绿色预览是否干净（见第 6 节）
- [ ] 没有发光、模糊、投影、文字、漫画符号（明确要求的除外）
- [ ] 每格互不重叠、不越界，格数和编号顺序正确
- [ ] 缩小检查：把图缩到每格约 128px 宽，还能认出动作和表情

## 6. 给接收素材的开发代理

- **美术约束不变**：游戏内互动画面里的角色只能来自用户确认的 Q 版素材。载入页的成年全息线稿保持原样，不由本批次替换。
- **转换**：用 `tools-art/convert.py`（v2，正常色转线稿加淡填色），步骤如下：
  1. 外轮廓：从白底泛洪得到剪影，在 3 倍工作分辨率下描一圈固定粗细的亮线（`OUTLINE_PX`）。
  2. 勾线：在工作分辨率下找比周围明显更暗的像素，用软阈值（`INK_CONTRAST`、`INK_SOFT`、`INK_RADIUS`）。缩小时细发丝已被平均掉，只剩主要勾线。
  3. 填色：按颜色分为肤色、白布、金饰、腮红、蓝色系五类，各自映射一档亮度（`FILL`）。蓝色系按原亮度在 0.07–0.17 之间分层，使头发和深色裙子分开；脸（0.36）比头发亮一档。
  4. 高光：剪影内部的小块纯白保留为最亮点。
  - 全部参数集中在 `PARAMS`。佩戴者反馈太亮或太暗时只改参数重新转换，不要让模型重画。
  - 新批次：`PYTHONPATH=build/pylibs python tools-art/convert.py --sheet <图> --kind body|bust --names a,b,...`。输出 `build/art/qban/<名字>.png`、绿色预览 `-preview.png`，以及记录基线偏移的 json。这一步不改动游戏数据，确认后再接入 `lib/sprite-data.js`。
  - 全身格用**统一比例**（按第一格 `body_front` 的剪影高度计算），不逐格归一化，否则跳跃、蹲下、坐姿的角色大小会不一致；脚底位置用 json 里的 `baseline` 对齐。
  - `--legacy` 输出旧算法结果到 `build/art/legacy/`，仅作对照。
- **镜像**：侧面类素材生成 `L` 镜像。有明确左右区别的素材（`bust_tilt_left/right`、`peek_edge`）不要用镜像代替。
- **体积**：每个全身精灵约 126×90 单通道，约 11KB，base64 后约 15KB；胸像约 40KB。全部 80 格约 1.5–2MB 的 base64，会拉长首屏解码时间。建议：
  - P0 素材随包加载。
  - P1/P2 按需分组解码，或者只在进入对应画面时才解码。
  - 解码依然走现有的分块预算。
  - 上真机检查首帧耗时和内存。
- **渲染**：不要用 `ctx.rotate / scale / transform` 来做歪头、翻转。所有角度变化都用预生成素材，Canvas 方法白名单见 `docs/LVFEIYU.md`。
- **体感互动**：`nod` 和 `shake` 事件在 0.4.0 真机日志中出现过。歪头、转头、抬头需要基于 `AbsoluteOrientationSensor` 的姿态角，阈值、保持时间和冷却时间都要先用只记录日志的版本让佩戴者试用后再定。
- **光学观感**：截图只能证明像素。填色亮度是否合适，由佩戴者在镜片上判断；如果偏亮或偏暗，调整 `PARAMS` 后重新转换，不要退回让模型重画。
